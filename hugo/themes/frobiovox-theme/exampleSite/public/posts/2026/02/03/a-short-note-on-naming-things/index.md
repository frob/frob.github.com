| description | Two paragraphs on why most variables don't need clever names. |


The longer I write code, the more I think the best names are the ones nobody will quote at a conference. `count`, `result`, `item`. Short, accurate, forgettable. The reader's attention is finite, and every clever name spends some of it.

Save the inventive names for the places where the concept is genuinely new — a module, a public function, a domain term. Inside a function, you almost never need a thesaurus. You need a noun and a context, and the context is the function itself.
