The basis of that post was clients asking for the <q>next</q> thing --expecting Drupal to be old and busted in five years.</p> <p>I am at ElixirConf because I see great potential in Elixir, Erlang, and <a href="http://www.phornixframework.com">Phoenix</a>. I expect it to be the next big thing and for it to help provide a scalable platform for highly available, highly scalable, and interactive / dynamic websites.</p> <p>I consider myself a technologist. As such, I am always looking for the <q>next</q> thing. However, I would caution my clients against it.</p> <h1>What is Elixir?</h1> <p>Elixir is a functional language that compiles down to Erlang. Erlang was developed by Ericson to run their phone switches. It is a fault-tolerant language that is designed to handle connections. However, Erlang is a difficult language to work with. Here are some examples about <a href="http://elixir-lang.org/crash-course.html">how Elixir simplifies Erlang</a>.</p> <h1>What is <a href="http://www.phornixframework.com">Phoenix</a>?</h1> <p><a href="http://www.phornixframework.com">Phoenix</a> is a Rails-like MVC framework that is written in Elixir. Phoenix makes good use of Elixir&#39;s tools (such as mix, plug, and ecto) and other Elixir components to create a highly scalable, fault-tolerant, and highly available web-application framework. This is still a very bare-bones and brand new framework. Phoenix 1.0.0 was just released. While I am very impressed, there are still some pieces that are missing. <em>Some of these piece are missing in Rails and other MVC based frameworks as well</em>. This is one reason I seldom use (or recommend) a MVC for back-end development.</p> <h2>Phoenix feature overview?</h2> <p>The thing to remember is that phoenix is a bare metal type of framework. All it gives the developer out-of-the-box are: <strong>Endpoints</strong>, <strong>Routes</strong>, <strong>Plugs</strong>, <strong>Models</strong>, <strong>Views</strong>, and <strong>Controllers</strong>.</p> <ul> <li><strong>Endpoints</strong> <ul> <li>Where the client can connect; web-sockets and http.</li> </ul></li> <li><strong>Routes</strong> <ul> <li>Paths to content, these can be dynamic.</li> </ul></li> <li><strong>Plugs</strong> <ul> <li>Modules of additional functionality. The connections is pushed through the Plugs and the Plugs affect the connection.</li> </ul></li> <li><strong>Models</strong> <ul> <li>Definition (schema) of data.</li> </ul></li> <li><strong>Views</strong> <ul> <li>How the data is displayed</li> </ul></li> <li><strong>Controllers</strong> <ul> <li>How the data can be manipulated.</li> </ul></li> </ul> <p>The nice thing about Phoenix is that it uses many pieces of tech form Elixir but it is also built to play well with other technologies.</p> <h1>Some not-scientific-at-all &trade; benchmarks.</h1> <p>I am testing with apache benchmark. Remember that when Drupal 7 was released, no one was even developing on Drupal 6 anymore --everyone was using Pressflow.</p> <p>Drupal 8, from all I can see, <em>gives us more tools out of the box than any other site building platform</em>.
